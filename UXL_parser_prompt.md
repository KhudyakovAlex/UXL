# UXL parser + HTML renderer (browser) — project prompt

Этот документ фиксирует текущие требования к парсеру/рендереру UXL в браузере. Дополнять его по мере новых требований.

## Цель

Сделать библиотеку `uxl.js`, которая:
- принимает UXL-текст и строит AST;
- валидирует (strict/permissive);
- рендерит в HTML (и частично SVG) по правилам из `UXL.md`;
- умеет работать “как mermaid”: исходник UXL может быть вставлен на страницу текстом и при показе в браузере заменяется на сгенерированный рендер.

## Входные данные UXL (кратко)

См. актуальную спецификацию: `UXL.md`.

### Ключевые правила парсинга

- UXL состоит из строк.
- Пустые строки игнорируются.
- Комментарии игнорируются: строка, у которой после отступов первый символ `;`.
- Вложенность задаётся отступом **двумя пробелами** за уровень:
  - табы запрещены;
  - “перескок” глубже больше чем на 1 уровень за строку — ошибка.
- Поля в строке тега разделяются `\`.
- Завершающий `\` не используется и запрещен (строго). В permissive можно либо считать ошибкой, либо аккуратно принять — но базовая цель: поддержать то, что описано в `UXL.md`.
- Тримминг: строка (после снятия отступа вложенности) триммится; каждое поле триммится. Для кавычечных полей пробелы внутри `"..."` сохраняются.
- Поля `CAPTION`, `HINT` (и текст ячеек `TH/TD`) могут быть:
  - некавычечными (без `\`);
  - кавычечными `"..."`, с `\"` и `\\`.

### Размеры

- **Опционально**: размер окна блока (первая значимая строка после ```UXL) задаётся как `WxH` (например `600x600`), `W` и `H` — целые, `> 0`.
- После опциональной строки размера окна **в корне блока разрешены только теги `P`**.
- Если содержимое страницы выходит за границы окна, оно **должно скроллиться при необходимости** внутри окна (P). По умолчанию поведение окна эквивалентно суффиксу `S`.
- Полосы прокрутки **не должны уменьшать рабочее поле**: размер окна `WxH` — это размер рабочей области, а скроллбары добавляются “снаружи”.
- Поле `SIZE`:
  - число без суффикса трактуется как px (суффикс `px` писать нельзя);
  - либо `%` (целое `0..100%`).
  - допускаются частичные формы: `Wx`, `xH`, `W%x`, `xH%`.

### ID

- Для страниц `P` поле `ID` **необязательное**:
  - допускаются формы `P\CAPTION[\HINT]` и `P\ID\CAPTION[\HINT]`.
  - если `ID` не указан, то `P\CAPTION\HINT` трактуется как CAPTION+HINT (а не как ID+CAPTION).
  - Если `GOTO` указывает на страницу, у целевой страницы должен быть задан `ID`.
- Для остальных элементов ID **не используется**.

### Форматы тегов (по тегам)

В проекте используется **отдельный формат полей для каждого тега** (ID используется только у `P`).
Для обратной совместимости допускается legacy-форма `TAG\\ID\\...` — поле `ID` при этом **игнорируется** для всех тегов, кроме `P`.

- `P`: `P\[ID]\CAPTION`
- `B`: `B\CAPTION[\...поля...]`  (пример: `B\Кнопка\100x\OUT:RB\GOTO:users\Назад`)
- `C`: `C\CAPTION[\...поля...]`  (поля в любом порядке)
- `F`: `F[\...поля...]` (поля в любом порядке, ACTION не используется)
- `I`: `I\SRC:<url>[\...поля...]` (поля в любом порядке; без CAPTION; без PADDING)
- `T`: `T\COLS:...[\...поля...]` (поля в любом порядке; `COLS:...` обязателен; ACTION у `T` не поддерживается: strict=ошибка, permissive=игнор)

Правило (кроме таблиц): для `B/C/F/T` поля (кроме `CAPTION` у `B/C`) могут идти **в любом порядке** и распознаются по виду:
- `SIZE`: содержит `x`
- `ALIGN`: задаётся как `OUT:<ALIGN>` (например `OUT:LT`, `OUT:B`; без `LR` и `TB`)
- `ACTION`: начинается с `GOTO:`
- `ICON`: `ICON:<name>[:size]` (встроенная пиктограмма для `B`, без внешних файлов). Пример: `ICON:search:18` (px, 8..48). Разрешены: ai, arrow-left, arrow-right, back, box, chevron-left, chevron-right, close, codepen, cpu, edit, grid, home, loader, microphone, plus, search, sun, settings, trash, volume-2. В `B` допускается форма `B\ICON:...` (иконка‑только, без CAPTION).
- `MARGIN`: `M<number>` (целые px, одно значение на все стороны; влияет на layout)
- `PADDING`: `P<number>` (целые px, одно значение на все стороны; влияет на layout)
- `RADIUS`: `R<number>` (целые px; пока используется только для `B` как скругление углов)
  - `BG`: `BG:<url>` (только для `F`) — фон контейнера картинкой по адресу (по умолчанию cover/center/no-repeat)
- `SRC`: `SRC:<url>` (только для `I`) — источник картинки
- `FIT/CROP`: `FIT` (contain) или `CROP` (cover) (только для `I`; если нет — без масштабирования). Legacy допускается: `FIT:contain` / `FIT:cover`.
- `RADIUS`: `R<number>` (целые px; используется для `B` и `I` как скругление углов)
- иначе — `HINT`
- `TH`: `TH\C\C\...`
- `TD`: `TD\C\C\...`

### Таблица без TC (COLS внутри T)

- Тег `TC` больше не используется.
- Колонки таблицы задаются в `T` через поле `COLS:...`, например: `T\COLS:20R,50L,30\100%x60%\OUT:T\Подсказка`
- `T\P<number>` задаёт **padding ячеек** (`TH/TD`) внутри таблицы.
- `T\M<number>` задаёт **margin** вокруг таблицы (внешний отступ).

Дефолтные значения (если поле не указано):

- `C`: `M3`, `P5`
- `B`: `M3`, `P5`, `R6`
- `T`: `P5` (ячеек `TH/TD`)
- иначе: `M0`, `P0`
- Правила `COLS`:
  - `COLS:` + список колонок через запятую
  - каждая колонка: `W` или `WA`, где `W` — целое 0..100, `A` — `L` или `R` (если нет — центр)
  - суммы процентов нормализуются до 100 детерминированно (как раньше в `TC`)

### Подпись страницы в рендере (если нет CAPTION)

- Если у страницы `P` нет `CAPTION`, в рендере показывается подпись **`P`**.
- Если при этом у страницы задан `ID`, подпись становится **`P <ID>`**.

### Переходы

- Переход считается только если `ACTION` имеет вид `GOTO:*`.
- `ID` case-insensitive, может начинаться с цифры.
- `GOTO` ссылается на страницу `P` по её `ID` (case-insensitive).
- В strict неизвестные `ACTION` — ошибка; в permissive — игнор.
- Для `T` поле `ACTION` не поддерживается: strict=ошибка, permissive=игнор.

### Ошибки

Если есть ошибка (парсинг/валидация), рендер должен **заменяться блоком ошибки**:
- текст ошибки;
- место (номер строки в UXL-блоке; по возможности — колонка);
- желательно: подсветка проблемной строки/фрагмента.

## Требования к рендеру в браузере

Рендер одного UXL-блока состоит из двух частей:

### 1) Карта интерфейса (вверху)

- Над картой выводится заголовок: **«Карта интерфейса»**.
- Прямоугольники страниц `P`, внутри — `CAPTION` страницы.
- Если `CAPTION` слишком длинный, в карте делаются переносы строк: **если больше 3 слов — переносить** (разбивать на строки по 3 слова).
- Между прямоугольниками стрелки переходов (по `GOTO`).
- Подписи на стрелках **не нужны**.
- Никаких дополнительных “плашек”/панелей вокруг карты: только прямоугольники страниц и линии/стрелки.
- Прямоугольники страниц в карте **не растягиваются на всю ширину**:
  - есть минимальная ширина;
  - при необходимости расширяются по `CAPTION`.
- Фон прямоугольников страниц в карте — такой же, как у “окна интерфейса” (canvas): светло-серый.
- Если переходов между страницами нет — страницы отображаются отдельно прямоугольниками.
- Если несколько элементов ведут из A в B — рисуем **одну** стрелку A→B.
- Если есть переходы в обе стороны A→B и B→A — рисуем **одну** линию A↔B со стрелками **на обоих концах**.
- Стрелки — SVG overlay поверх прямоугольников.
- Клик по прямоугольнику страницы в карте прокручивает документ к соответствующей странице ниже (заголовок страницы оказывается у верхней границы окна браузера).
- Линии должны быть “ломаные” с плавными (скруглёнными) перегибами.
- Соединения в карте — тонкие, и на конце линии должна быть **стрелка** по направлению перехода (A→B).
- При двунаправленном переходе A↔B должны рисоваться **две** стрелки, разнесённые по вертикали (чтобы не накладывались).
- Раскладка страниц в карте — **в виде дерева по переходам**:
  - “главная” страница (root) — **первая `P` в UXL-блоке**, слева сверху;
  - страницы следующего уровня располагаются правее (уровни увеличиваются вправо).

### 2) Блоки страниц (ниже)

Для каждой страницы `P` (в порядке в тексте):

- Заголовок: `<CAPTION>` (или `P` / `P <ID>`, если CAPTION пустой).
- Под заголовком — две колонки:
  - слева: рендер страницы (layout по `SIZE` + `ALIGN`, контейнеры `P/F/T`, элементы `B/C`, таблицы `T/TC/TH/TD`);
  - справа: список хинтов — **только элементы с непустым `HINT`** (текст строки = `HINT`).
- Список хинтов — без фоновой плашки и без заголовка “Hints” (просто список текста).
- Текст хинтов — **тёмно-красный**, как и линии/кружки отводок.
- От каждой строки хинта должна идти линия-отводка к соответствующему элементу на рендере:
  - SVG overlay;
  - ломаные со скруглёнными перегибами (плавные линии);
  - линия тонкая, **пунктирная**, цвет — **ярко-красный**;
  - в точке прихода на элемент — маленький кружок **залитый**, ярко-красный (примерно в 2 раза меньше прежнего);
  - линия начинается от отдельного пустого кружка рядом с текстом хинта (не от стандартного маркера списка).
  - кружок прихода линии ставится **на краю элемента со стороны списка хинтов** (т.е. на правой грани элемента), а не в центре.

### Переход по клику (GOTO)

- Если у кнопки `B` задан `ACTION` вида `GOTO:<ID>`, при клике браузер прокручивает документ к соответствующей странице `P` так, чтобы её заголовок оказался у верхней границы окна браузера.
- Переход возможен только на страницу с заданным `ID`.

### Визуальные ограничения

- Скругления **не используются** в UI (прямые углы), кроме плавных перегибов у линий-отводок/стрелок.
- Фон “окна интерфейса” (canvas, область рендера экрана) — **светло-серый**.
- `F` — полностью невидимый элемент: используется только для layout/вёрстки, как отдельный прямоугольник не рисуется.

### Правило раскладки (без перекрытий на одном уровне)

Для рендера в браузере используется “анти-перекрытие” для элементов одного уровня внутри одного контейнера:
- элементы, привязанные к краям (`L`/`R`/`T`/`B` без растяжения по этой оси) **резервируют** место у соответствующего края (если их размер по этой оси задан);
- элементы, которые **растягиваются** (`LR`/`TB`) или стоят **по центру** (без `L/R` или без `T/B`), раскладываются внутри оставшейся области (контент-бокса), чтобы “упираться” в зарезервированные элементы вместо перекрытия.

## Mermaid-like режим

На HTML-странице исходный UXL может быть вставлен “как текст”. При загрузке страницы JS должен:
- найти такие блоки (по классу/селектору);
- извлечь UXL;
- заменить исходник на рендер (или на ошибку).

Важно: библиотека парсера/рендера не должна зависеть от того, как именно UXL попал в HTML. Для `index.html` можно просто вставить UXL вручную.
