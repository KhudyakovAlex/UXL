# User Experience Language

Язык описания интерфейсов для UX-дизайна в MD-файлах.

Служит для последующего рендеринга в HTML.

## Структура UXL-блока в MD-файле

Начало блока UXL: ```UXL  

Окончание блока UXL: ```  

Первая значимая строка после ```UXL может задавать размер окна. Размер задается в пикселях в формате `WxH` (например, `800x600`). Суффикс `px` **писать нельзя**.

Правила чисел для размера окна:
- `W` и `H` — **целые числа** (дробные значения запрещены);
- `W > 0`, `H > 0`.

Если первая значимая строка не содержит размер (пустая или сразу начинается с тега P), размер окна считается `500x500`.  

Значимые строки:
- пустые строки игнорируются;
- строки-комментарии игнорируются (строка, у которой после отступов первый символ `;`).

Каждый новый тег элемента начинается с новой строки.  

Вложенность элементов определяется отступами:
- каждый уровень вложенности добавляет ровно два пробела к отступу предыдущего уровня;
- табы запрещены;
- “перескок” на несколько уровней глубже за одну строку (например с 0 сразу на 4 пробела) считается ошибкой.

В корне блока — только теги P.

## Режимы парсинга (strict / permissive)

Рекомендуется поддерживать два режима:
- **strict** — любые нарушения спецификации считаются ошибкой и блок не рендерится.
- **permissive** — некоторые нарушения допускаются с нормализацией/игнорированием (см. отдельные пункты ниже).

## Теги элементов

P - Страница  
F - Область для разметки, невидима в рендере, может содержать другие элементы   
B - Кнопка  
C - Надпись    
T - Таблица (контейнер для TC, TH, TD)  
TC - Форматы колонок  
TH - Ячейки заголовка  
TD - Ячейки с данными  

## Разрешенная вложенность (валидация структуры)

- В корне блока разрешены только `P`.
- `P` может содержать: `F`, `B`, `C`, `T`.
- `F` может содержать: `F`, `B`, `C`, `T`.
- `T` может содержать только: `TC`, `TH`, `TD` (и ничего больше).
- `TC`, `TH`, `TD`, `B`, `C` не могут иметь дочерних элементов.
- `P` не может быть вложенным элементом (страницы не вкладываются).

## Формат тегов

### Формат тегов по умолчанию

TAG\ID\CAPTION\SIZE\ALIGN\ACTION\HINT  

где составляющие:  
- TAG - тег элемента
- ID - ID для идентификации внутри блока UXL
- CAPTION - строка, отображаемая у некоторых элементов в рендере
- SIZE - размеры элемента
- ALIGN - выравнивание элемента
- ACTION - действие при клике на элемент
- HINT - подсказка, всплывающая при наведении курсора на элемент

### Разделитель и правила текста (важно для парсера)

- Символ `\` является разделителем полей.
- **Завершающий `\` не используется и запрещен**: если после последнего указанного поля дальше ничего нет, разделитель `\` не пишется.
- **Тримминг**: после снятия отступа вложенности вся строка триммится по краям; затем каждое поле триммится по краям. Для кавычечных полей тримминг применяется к области *вне кавычек*; пробелы внутри `"..."` являются частью значения.
- Поля `CAPTION`, `HINT` (и текст ячеек таблицы) могут быть:
  - некавычечными: любая строка без `\` (пробелы допустимы);
  - кавычечными: `"..."` — внутри допускаются `\"` (двойная кавычка) и `\\` (обратный слэш).
- Поле считается кавычечным, если первый символ значения поля — `"`.
- В некавычечной форме символ `\` запрещен. Если нужен `\` — используйте кавычечную форму.
- Пустое значение поля задается как “ничего между разделителями” (то есть `\\` в исходном тексте).
Пример (кавычечное поле): `C\\"Путь: C:\\Temp"\200x20\LT`.

#### ID
Обязателен только для тега P (страница). Для остальных элементов может использоваться, но необязателен.
Строка из латинских символов, цифр, подчеркивания, дефиса. **Может начинаться с цифры.**
**Регистр неважен**: сравнение `ID` и проверка уникальности выполняются case-insensitive.
`ID` должен быть уникальным в пределах типа тега. Например, могут существовать одновременно `P1` и `F1`, но не может быть двух `P1` (включая вариант `p1`).

#### CAPTION
Строка: надпись на кнопке, содержимое надписи и т.п.

#### SIZE
Ширина и высота элемента в формате: `WxH` (ШИРИНАxВЫСОТА).  
`W` и `H` задаются:
- либо **в пикселях по умолчанию**: целое число без суффикса (например `330`). Суффикс `px` **писать нельзя**;
- либо **в процентах** от внутреннего размера контейнера-родителя: целое число с суффиксом `%` (например `33%`).

Правила чисел для `SIZE`:
- пиксели: целое число `>= 0`;
- проценты: целое число от `0%` до `100%` включительно;
- дробные значения запрещены; отрицательные значения запрещены.
Можно указать только ширину (`Wx` или `W%x`) или только высоту (`xH` или `xH%`). Если размер не указан или указан частично, недостающая часть определяется содержимым элемента.

#### ALIGN
Выравнивание по горизонтали и вертикали в пределах элемента-родителя в формате: LRTB.
L - привязка к левому краю,  
R - привязка к правому краю, 
LR - растягивает элемент во всю допускаемую элементом-родителем ширину.  
Если не указаны ни L ни R, выравнивание по горизонтали по середине.
T - привязка к верхнему краю,  
B - привязка к нижнему краю, 
TB - растягивает элемент во всю допускаемую элементом-родителем высоту.  
Если не указаны ни T ни B, выравнивание по вертикали по середине.
Можно комбинировать горизонтальное и вертикальное выравнивание: LT (левый верхний угол), RB (правый нижний угол), LRTB (растягивание на всю область) и т.д.

#### ACTION
Одна из команд:
- GOTO:ID - переход на страницу `P` с указанным `ID` (например, `GOTO:login` означает переход на страницу `P\login\...`).
- Для обратной совместимости допускается старая форма `GOTO:P<ID>` (например, `GOTO:Plogin`) и трактуется как `GOTO:<ID>`.
`ID` в `GOTO` сравнивается case-insensitive.

### Порядок составляющих

Составляющие кроме тега могут отсутствовать.
Составляющие должны быть на своих местах, т.е., если какая-то составляющая отсутствует, её место должно быть занято пустым значением (два обратных слэша подряд \\ означают пустое значение).
Если после указанного поля других полей нет, то завершающий `\` **не нужен и запрещен**.
Если у тега есть хотя бы одно поле, после `TAG` ставится `\` (как разделитель между `TAG` и первым полем).
Примеры:
- B\12\Кнопка\\LRTB\GOTO:2 (здесь SIZE отсутствует, поэтому два слэша подряд)
- C\\Текст\100x20 (здесь ID отсутствует, так как для C он не используется)
- B\\Войти\100x30\LT\GOTO:login

### Формат тегов таблицы

Таблица (T) является контейнером и содержит структуру: TC → TH → TD.
В таблице сначала идет `TC` (обязательно), затем `TH` (0 или 1 раз), затем `TD` (0 или более раз).

Примечания к тегу `T`:
- `T` использует общий формат `TAG\ID\CAPTION\SIZE\ALIGN\ACTION\HINT`, но на практике у `T` обычно не задают `ID`, `CAPTION`, `ACTION` (их следует оставлять пустыми), а используют `SIZE`, `ALIGN` и при необходимости `HINT`.
- `ACTION` для `T` не поддерживается:
  - в **strict**-режиме: наличие непустого `ACTION` у `T` считается ошибкой;
  - в **permissive**-режиме: `ACTION` у `T` игнорируется.

#### TC - Форматы колонок

TC\WA\WA\WA\...

где:
- W - ширина колонки в %, **целое число от 0 до 100**
- A - выравнивание в ячейке колонки по горизонтали: L или R; если не указано - выравнивание по середине
Дробные проценты недопустимы. Отрицательные значения запрещены. Некорректные значения (нечисло/вне диапазона) — ошибка.

Сумма процентов всех колонок должна равняться 100%. Если сумма отличается от 100%, колонки **детерминированно** нормализуются до суммы 100:
- Если сумма равна 0 — ошибка.
- Иначе для каждой колонки вычисляется `raw = W * 100 / sum` (с дробной частью).
- Итоговая ширина `W'` берется как `floor(raw)` для всех колонок, затем оставшиеся проценты (`100 - sum(floor(raw))`) раздаются по 1% колонкам с наибольшей дробной частью `raw` (при равенстве — слева направо).
Пример: TC\20R\70L\10

#### TH и TD - Ячейки таблицы

TH(или TD)\C\C\C\...

где:
- C - текстовое содержимое ячейки
Пример: TD\100\Жигулевское\- (здесь "-" - это текст в ячейке, а не пустое значение)

Пустая ячейка задается как пустое значение поля: например `TD\1\\100` (вторая ячейка пустая).
Количество ячеек в `TH` и `TD` должно соответствовать количеству колонок, указанному в `TC`.

### Формат тегов P

P\ID\CAPTION

где:
- ID - Строка из латинских символов, цифр, подчеркивания, дефиса; может начинаться с цифры; уникальна в пределах типа тега (case-insensitive).
- CAPTION - Заголовок страницы

Если в строке `P` указаны поля правее `CAPTION` (например `P\id\cap\100x100\...`):
- в **strict**-режиме это считается ошибкой;
- в **permissive**-режиме эти поля игнорируются.

## Рендеринг

В итоговом рендере должна по умолчанию показываться первая страница в блоке.

### Модель layout (чтобы рендер был однозначным)

- Каждый `P`/`F`/`T` образует прямоугольный контейнер (box) со своей внутренней областью.
- Дочерние элементы позиционируются относительно внутренней области контейнера по `SIZE` и `ALIGN`.
- Если `SIZE` не задан:
  - ширина/высота считаются “по содержимому” (intrinsic size) с учётом базовых стилей рендера;
  - если при этом в `ALIGN` указан `LR`, ширина принудительно растягивается на всю доступную ширину контейнера;
  - если в `ALIGN` указан `TB`, высота принудительно растягивается на всю доступную высоту контейнера.
- Если задано значение в процентах, процент берется от внутреннего размера контейнера-родителя по соответствующей оси.
- В UXL нет авто-раскладки (flow/layout): если два элемента привязаны к одному месту, они могут перекрываться.
- Порядок перекрытия (z-order): элементы, объявленные ниже в тексте (позже), рисуются поверх более ранних.

### Ошибки и валидация (рекомендуемый strict-режим)

Рекомендуется считать ошибкой и не рендерить блок, если:
- нарушены правила отступов/вложенности;
- в корне встречаются теги, отличные от `P`;
- дублируются `ID` в пределах одного типа тега;
- `GOTO` ссылается на несуществующую страницу `P\ID\...`;
- у таблицы `T` отсутствует `TC` или количество ячеек в `TH`/`TD` не совпадает с количеством колонок в `TC`;
- встречаются неизвестные теги или неизвестные команды `ACTION`.
